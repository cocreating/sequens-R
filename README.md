# sequens-R

sequens-R is a local-first, generative MIDI sequencer for Chromium-based browsers. It is being built from the project SDD in discrete, verified phases.

## Project status

Phases 1, 2, and 4 are complete and pass their automated Definitions of Done. Phase 3 implementation and automated acceptance are also complete: Web MIDI is opt-in, routing is per module, notes and 24 PPQ clock use absolute timestamps, and the app exports SMF Type 1, offline WAV mixes, and zipped WAV stems. Physical 10-minute clock/jitter measurement and three-DAW import checks remain before the Phase 3 gate can be marked accepted.

At 1024 CSS px and wider, Phase 4 adds the parallel-lane desktop studio, Arp, Euclid, Piano roll, CC Control, Mod, multiple racks, keyboard shortcuts, selectable audio output, and File System Access saves. Every desktop module panel also has an opt-in contextual Help mode: hovering a control or reaching it with the keyboard updates a stable in-panel explanation while leaving the instrument usable. Phase 6 supersedes the original mobile playback-only plates with adaptive editors. Manual Piano roll data and recorded CC motion still use project export instead of compact link sharing.

The Piano roll now includes a persistent velocity lane, accents, non-destructive loop shortening, scale-degree and octave transforms, selectable Chords context with chord stamping, routed note audition, a labelled pitch keyboard, and Fit/50/75/100/150/200% zoom. Its `Load melody` selector provides 20 original key-aware phrases ordered from simple to advanced; loading a phrase is one undoable edit and synchronizes the active slot to its native 16-, 32-, or 64-step length. See the [Piano Roll Pro implementation and evidence](.agents/docs/piano-roll-pro.md).

Phase 5 implementation and automated acceptance are complete. It adds quantized scenes, Media Session and Wake Lock integration, background recovery, compositor playheads, progressive View Transitions and background task scheduling, the Acid TPT ladder worklet, live audio diagnostics, a top-right General Help mode for contextual panel and control guidance, and the full accessibility pass. Playheads remain visible as discrete step indicators when Android Chrome reports reduced motion, while the default presentation stays smooth. The four optional backlog modules remain deliberately deferred because the SDD requires demonstrated usage first. Physical mid-range Android measurements for all seven C10 budgets remain before the Phase 5 gate can be marked fully accepted.

Version 0.1.0 consolidates the studio UI around the performance path. The sticky `app-header` owns one flattened `app-header-controls` group on every viewport: visible `TAB`, icon-only Tempo and Key, Workspace, Mixer, the visibly labelled Add Module action, Random, Stop, Share, General Help, and Play/Pause stay in coherent DOM order and wrap naturally without breakpoint-specific duplicates or redundant action wrappers. Tempo opens a keyboard-accessible whole-number BPM panel with number and vertical slider controls. Key opens one combined panel whose root-note and scale grids remain available together, so both values can be changed without reopening the panel; neither musical value uses a header select or label. Add Module opens a keyboard-accessible visual library of all eleven named module types, each with an icon and short purpose statement, replacing the former module-type select. Mixer is the sole permanent rack-mix panel beside Workspace and is not a module type. Its full-width responsive grid targets three compact channels per mobile portrait row and expands through four, five, or six columns on wider landscape/desktop surfaces. Each channel places a 12-segment LED meter directly beside its vertical fader; PAN and SENDS start globally hidden, with PAN above Delay/Reverb when revealed on desktop. Repeated taps set a smoothed whole-number BPM. Pause preserves the exact transport beat and freezes every playhead, Play continues from it, and Stop resets to zero. Module headers now follow reorder → desktop full-width → collapse → editable name → actions; the collapse chevron points right when closed and down when open. Mobile reaches the rack immediately and places the compact `s-R` mark inside a padded decorative circle, while desktop keeps the full title, `Local generative MIDI` subtext, and a build-derived current-version badge. A fixed up-arrow appears after meaningful downward scrolling and returns to the top with reduced-motion support. Project, rack, scene, hardware, export, and diagnostics tools open in responsive top-layer panels, leaving the module rack at full width on every surface. Any desktop module can temporarily span the full lane row. New projects use the clear `New Project` default; saved documents using the former `Untitled Project` default migrate automatically. Module plates expose pattern and musical parameters first, move routing and deterministic scheduling into an `Output & advanced` disclosure, and use schema-selected knobs, steppers, segmented controls, switches, selects, and mixer faders instead of a single slider language. Recognizable frequent actions use a shared dependency-free outline-SVG icon component with explicit accessible names; ambiguous, destructive, recording, mutation, launch, routing, and module-menu commands retain visible text. **Drone module implemented; listening acceptance open.** Drone adds two-to-four-voice continuous, key-aware harmonic fields with six seeded layouts, one-to-eight-bar cycles, uninterrupted anchor coverage, slow upper-voice changes, eight pattern slots, MIDI/SMF output, compact sharing, and a four-lane persistent procedural voice. The application deliberately uses Svelte 5 with Vite rather than SvelteKit. sequens-R is currently a single-screen, client-only, offline-first instrument, so SvelteKit's routing and server-rendering facilities would add browser/SSR boundaries without improving AudioWorklet scheduling or synthesis performance. This decision should be revisited if the product gains multiple routes, server endpoints, authentication, cloud storage, or a separately prerendered public site.

## Local development

Requirements: Node.js 20.19 or newer and Google Chrome.

```bash
npm install
npm run dev
```

The Vite server sends COOP/COEP headers. Open the printed localhost URL rather than opening `index.html` directly.

## Bundled demo projects

The Workspace demo picker ships twenty schema-version-7 electronic projects, classified into three genres: Minimal Techno (7), Minimal House Techno (7), and Ambient Techno & Breakbeats (6). Each demo rebuilds a recognisable rhythmic archetype from the recorded history of electronic music — a Detroit loop, a krautrock motorik pulse, a Chicago jack, a Cologne schaffel limp, a Berlin School sequencer run, a Kraftwerk-lineage electro displacement, a two-step garage break — using only this instrument's deterministic generators. What is borrowed is the grid and the gesture; no melody, bass line or chord progression is taken from the records that inspired a demo, and no demo carries an artist or record name in its title.

Every demo uses two or three modules and declares at most four drum sounds, and that four-sound limit holds in all eight pattern slots. Tempos range from 84 to 168 BPM. Nineteen demos carry one Synth; Sequencer Field is Arp plus Drone, because a Berlin School sequencer piece has no lead voice. Selected Drift and Sequencer Field have no drums at all. The four scenes — Intro, Groove, Variation, Peak — form one arc rather than four takes: Intro uses each generator's thinnest variant, Variation displaces without adding weight, and Peak uses the densest.

The demos store their channel levels, pan, sends, delay/reverb returns, and master character in the rack's normal mix state. Mixer is a permanent header panel rather than a creatable module; use the button beside Workspace to edit the shared rack mix. The original Basic Electro file remains an unlisted migration fixture and is not part of the twenty-project shipping catalog.

The catalog and its JSON files live under [`public/projects/`](public/projects/). Regenerate all twenty projects deterministically with `npm run demos:generate`. See the [demo-project library reference](.agents/docs/demo-projects.md) for the complete matrix and verification contract.

The studio visual refresh re-skins the instrument without moving a single control. Module containers become milled plates: a top-to-bottom gradient, a 1px inset highlight, a hairline ring, and a soft drop shadow replace the former nested bordered boxes. Module identity moves from a whole-plate background tint to a 4px full-height hue spine plus a type chip, so the eleven user-selectable colours now read as identity marks rather than washes; only the colour id is persisted, so every saved project is unaffected. Lime is reserved for signal — playing, armed, selected, active — and is never a border or a decoration: step pads, pattern slots, scene launches, the Play button, and the playhead carry it as fill or glow. Step grids, the piano roll, slot rows, meters, and segmented controls sit in recessed wells so controls read as set into the panel rather than laid on it. Every label is condensed uppercase Barlow Condensed and every number is JetBrains Mono with tabular figures, both self-hosted from `public/fonts/` so the offline shell keeps its typography. Three existing style assertions contradicted the new language and were amended in place with their intent preserved rather than removed. See [architecture decisions](.agents/docs/architecture-decisions.md) AD-017 and AD-018 for the accepted deviations, including the WCAG AA contrast floor that overrides the handoff where a recipe would drop small text below 4.5:1.
